# Dead-code / unused-code tooling for bucketer — design

- **Date:** 2026-09-13
- **Status:** draft (awaiting operator spec review)
- **Blast radius:** T-tool (adds a quality gate to pre-push + CI)
- **Method:** 4-agent read-only panel (frontend/infra/qa/architect) → this synthesis. Lane reports: `docs/review-deadcode-tooling/{frontend,infra,qa,architect}-lane.md`.
- **Scope (operator-fixed):** unused **files / exports / deps / imports / CSS classes** only. NOT lint / formatting / complexity / style.

## 1. Decisions locked

| # | Decision | Choice | Source |
|---|---|---|---|
| A | Pre-push posture day one | **Staged**: pre-push prints findings but exits 0 (bake-in); CI blocks from day one; flip pre-push to blocking after a clean streak | operator 2026-09-13 |
| B | Baseline rot | **Bidirectional ratchet**: fail on new findings AND on stale baseline entries (code fixed but entry left) | operator 2026-09-13 |
| C | Unused imports | **Included** (in-family with unused code; knip reports for free) | adopted default (architect) |
| D | CSS gating | **Report-only / advisory**, never blocking, until fidelity proven | adopted default (all lanes) |
| E | Fleet scope | **Pilot in bucketer only**; propose as repo-baseline §8 watch-item after a few clean cycles | architect (standards-vs-happenstance test fails today) |

## 2. Tool selection

**Primary: `knip`** (pinned exact version) for unused files, exports, deps, and imports.
- Only actively-maintained tool covering files+exports+deps for **plain JS/JSX (no TypeScript)** in one config. depcheck & unimported are ~3yr stale (depcheck's maintainers point to knip); ts-prune is archived + TS-only; ESLint/oxlint/Biome cannot do cross-file unused-export/file detection (single-file scope only).
- Deterministic per pinned version; no network/AI step.
- Installs on `node:20-alpine`: its native dep `oxc-parser` ships `x86_64-unknown-linux-musl` prebuilt binaries (same class as the existing `esbuild` devDep). **Verify at integration** with `npm ci && npx knip --version` in the alpine image.

**CSS: PurgeCSS report-only** (`@fullhuman/purgecss`, Node API) as a separate, narrow check.
- knip's CSS-class detection is Tailwind-v4-specific; `src/styles/main.css` is hand-authored BEM-ish → not covered by knip.
- Run via a standalone script (`scripts/check-unused-css.mjs`), **never wired into `build.mjs`** — the byte-reproducibility invariant must not depend on a class-usage heuristic.
- `content` glob `src/**/*.{js,jsx}` + `src/index.html`; **safelist** the dynamic-class prefixes (see §3 trap 3).

## 3. knip config — the five false-positive traps

Config correctness is the whole ballgame; a mis-curated config → false positives → ignore-fatigue → a silently-void gate.

```jsonc
// knip.json
{
  "$schema": "https://unpkg.com/knip@5/schema.json",
  "entry": [
    "src/main.jsx!",                       // esbuild bundle root
    "src/worker/zip-assembler.worker.js!"  // TRAP 1: separate esbuild entrypoint,
                                           // wired by the __WORKER_SRC__ string
                                           // substitution in build.mjs — NOT reached
                                           // through the src/main.jsx import graph.
  ],
  "project": ["src/**/*.{js,jsx}"],
  "ignore": ["src/lib/changelog.js"]       // @generated by build.mjs from CHANGELOG.md
  // build.mjs / serve.mjs / scripts/*.mjs / perf/*.mjs / test trees are non-src
  // entrypoints — declare or exclude so they aren't reported unused.
}
```

Traps and their handling:
1. **Inlined worker** (`src/worker/zip-assembler.worker.js`) — declared as a second `entry`. (`assembler-worker-url.js` needs nothing: it's statically imported by `App.jsx`.)
2. **Test-only exports (~40)** — two-run strategy: `knip` (tests count as consumers) → anything still flagged is unused by BOTH src and test = **truly dead**. `knip --production` → exports clean in run 1 but flagged here are **test-only** (gray). Report gray separately; do NOT auto-fail on it.
3. **Dynamic CSS classes** — confirmed broad (≥10 sites: `toast-${type}`, `logo-phase-${phase}`, `status-badge ${cls}`, `upload-item-status ${…}`, etc.). Handled entirely on the PurgeCSS side via a **safelist** of prefixes; enumerate by grepping `` class={`…${ `` once and maintaining the small list.
4. **Dormant vault** — `src/lib/vault.js` is statically imported (gated by a runtime flag, not a dead import) → graph already sees it as used; no file-level special case. Only its test-only exports fall into the trap-2 gray bucket; a truly-orphaned dormant export gets a `deadcode-baseline.json` entry (reason `dormant-feature`), never a whole-file ignore.
5. **Non-graph entrypoints** — `build.mjs`, `serve.mjs`, `scripts/*.mjs`, `perf/*.mjs`, and the `test/**` trees declared/excluded so they aren't false-flagged.

## 4. Gate integration

- **New CI job `deadcode`** (own pipeline dot, `node:20-alpine`, `test` stage, parallel to `test`/`e2e-*`, **not** folded into `test`). Blocks from day one. No build needed (source-only) → no coupling to the stale-dist guard, no effect on `reproducibility`.
- **Pre-push step** added as the FIRST action after the branch-ref check in `.githooks/pre-push` (before `npm run build`), so it fails in seconds not minutes. **Warn-only (exit 0) during bake-in**, per decision A.
- **Pinning:** exact version in `package.json` devDeps (no caret) — unused-code heuristics shift between minors. A small assertion in the `source-invariants.test.js` family fails loudly if the pin regresses to a range.
- **Reporting:** rely on knip's native exit codes (0 clean / 1 findings / 2 config error). CI: `codeclimate` reporter → GitLab `codequality` MR-widget artifact if the pinned version supports it; else plain console + JSON artifact. (Confirm reporter flags against the pinned version.)
- **npm script:** one `npm run deadcode` runnable identically locally and in CI (baseline §4 light-parity).

## 5. Baseline (`deadcode-baseline.json`, repo root)

One entry per accepted finding:
```json
{ "file": "src/lib/vault.js", "identifier": "unlockVault", "kind": "export",
  "reason": "dormant-feature", "note": "Login-vault Phase 2, gated off — see #<issue>", "added": "2026-09-13" }
```
- `reason` ∈ closed enum `{dormant-feature, test-only, todo-remove}`; `note` required.
- **Bidirectional ratchet** (decision B): a wrapper script diffs current findings vs baseline. New non-baselined finding → fail. Baseline entry no longer matching any finding → fail with "delete the stale entry." Baseline can only shrink or turn over.
- **False positives are fixed in config, never baselined** — baselining an FP permanently masks it even if the code later becomes genuinely dead.
- Reviewed by construction: a baseline addition shows in the MR diff like an `eslint-disable`.
- **Schema guard** as a `source-invariants`-style unit test: every entry has non-empty `file`/`identifier`/`note` and a `reason` in the enum. (Detection logic does NOT go in source-invariants — that idiom is point assertions, not whole-graph reachability.)

## 6. Acceptance procedure (run at integration; paste output into the BUG-LOG-style record)

1. **True-positive matched pair:** append `export function __deadcodeProbe(){return 1;}` to `src/lib/format.js` (referenced nowhere) → run gate → expect **RED** naming `format.js:__deadcodeProbe`. Remove → **GREEN**.
2. **FP zero-finding (config, not baseline):** confirm `src/worker/zip-assembler.worker.js` and the dynamic CSS classes produce **no finding at all** (not a baselined finding).
3. **Test-only gray:** confirm the chosen two-run config reports test-only exports separately without failing the blocking gate.
4. **Dormant vault:** run the tool, baseline only the *specific* vault exports it flags (reason `dormant-feature`), never the whole file.

## 7. Coherence with existing gates

Four disjoint mechanical layers — no overlap:

| Layer | Question | Locus |
|---|---|---|
| `build.mjs` invariants | Is build *output* structurally correct? | build-time |
| `source-invariants.test.js` | Is *required* semantic code present? | unit test |
| stale-dist + reproducibility CI | Does committed bundle match a deterministic fresh build? | CI |
| **dead-code tool (new)** | Is any source *unreachable / unused*? | new check, existing runner |

Rule written into the repo: the dead-code tool never absorbs a source-invariant, and no existing invariant migrates into it.

**Value framing:** dead code already tree-shakes out of the single-file bundle and the size tripwire guards bloat — so this gate buys **source-tree legibility + an honest dependency manifest**, not ship-safety. This is why it pilots (not baseline-now) and why staged pre-push is calibrated.

## 8. Rollout sequence

1. Worktree off local `main` (includes held v1.59.4). Install knip + purgecss (exact pins).
2. Author `knip.json` + `scripts/check-unused-css.mjs` + `scripts/deadcode-gate.mjs` (ratchet wrapper) + `npm run deadcode`.
3. First real `npx knip` run → curate config until FPs are zero; classify remaining findings; build `deadcode-baseline.json` deliberately.
4. Add the pin-exact assertion + baseline schema-guard test.
5. Wire the CI `deadcode` job (blocking) + the pre-push warn-only step.
6. Run the §6 acceptance procedure; paste evidence.
7. Version bump + CHANGELOG + rebuilt dist; operator-confirmed push (folds in v1.59.4 + the dead-CSS work).
8. Flip pre-push to blocking after a clean streak (future, separate small change).

## 9. Open risks / verify-at-integration

- **knip `node:test` auto-discovery** — whether plain `node --test` files are auto-detected as consumers or need explicit `project` listing (its plugins document Jest/Vitest, not node:test). The two-run diff works either way; exact wording may need adjustment. **Unverified.**
- **`MAX_CONCURRENCY` in `zip-prefetch.js`** flagged as genuinely dead by the frontend lane (zero refs src+test) — confirm against real tool output; treat lane example lists as spot-checks, not an inventory.
- **CSS fidelity** — the highest FP risk; keep CSS report-only until the safelist is proven complete.
- **`oxc-parser` on alpine** — point-in-time fact; confirm at integration.
- **Reporter flags** — contingent on the exact pinned version.

## 10. Non-goals

Lint / formatting / naming / complexity (different tool class, different value, larger argument surface — its own proposal if ever wanted). Fleet-wide adoption now. Blocking CSS gate now. Removing any currently-baselined gray-area code (that's a separate design decision per export).
